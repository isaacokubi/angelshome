# Angels Home production readiness

This runbook covers the operational controls needed before deploying the school platform for a paying school.

## Timetable

The SMIS timetable workflow is enforced as:

`Classes → Subjects → Class-specific teacher allocations → Weekly lesson counts → School periods → Whole-school generation`

The master timetable is generated across the whole school. Teacher/class collisions must be rejected before lessons are saved. Locked timetables must not be edited until an administrator unlocks them. Teacher, pupil and parent timetable views must remain scoped to the authenticated user's permitted teacher or linked pupil/class.

## Notifications

Lesson reminders are generated by the server scheduler. In-app notifications should be persisted in MongoDB so they survive page refreshes. SMS delivery is optional and must be configured with the school's approved provider credentials. Browser audio requires user permission/interactivity; the UI should provide a notification sound for the configured reminder window without relying on a background tab being able to autoplay audio.

## Authentication

Production requires:

- `JWT_SECRET` of at least 32 random characters.
- `MONGO_URI` pointing to the production database.
- `CLIENT_ORIGINS` containing only the real school frontend origins.
- HTTPS at the frontend and API edge.
- No administrator credentials committed to source control.
- Pupils cannot self-edit phone numbers; parent contact changes synchronize linked pupils and administrator corrections are audited.
- Login, registration and password-reset endpoints should be rate limited.

Run `npm run check:production` in `server/` before deployment.

## Security

The API uses Helmet, CORS allow-listing, request size limits, rate limiting, Mongo sanitization, XSS sanitization, disabled `x-powered-by`, and production-safe error responses. Keep secrets only in the deployment provider's secret store.

## Backups

A manual backup can be created with:

```bash
npm run backup:database
```

The repository also includes a scheduled GitHub Actions backup workflow. Configure these repository secrets before enabling it:

- `MONGO_URI`
- `BACKUP_ENCRYPTION_KEY`

Backups are encrypted with AES-256-CBC before the artifact is uploaded and are retained for 14 days. A real production service should additionally copy encrypted backups to independent storage and perform a restore test at least monthly.

## Reporting

Administrative reports must use server-side authorization and aggregate from the same live records as the SMIS modules. Exported reports should be treated as sensitive school records and should never expose data outside the requesting administrator's scope.

## Deployment

### Frontend

- Set the production API URL in the Vercel environment as `VITE_API_URL`.
- Configure SPA rewrites so direct portal routes work on refresh.
- Deploy only from the protected production branch.

### Backend

- Set `NODE_ENV=production`.
- Set `PORT` from the platform-provided port.
- Set `MONGO_URI`, `JWT_SECRET`, and `CLIENT_ORIGINS`.
- Configure SMS/WhatsApp credentials only when those integrations are enabled.
- Use HTTPS and a managed domain.
- Configure health monitoring against `/health` and readiness monitoring against `/ready`.

### Release gate

Run:

```bash
npm --prefix client ci
npm --prefix client run lint
npm --prefix client run build
npm --prefix server ci
npm --prefix server run check:production
find server -type f -name '*.js' -not -path 'server/node_modules/*' -print0 | xargs -0 -n1 node --check
```

Do not promote a release when lint, build, syntax validation, production environment verification, or timetable integrity checks fail.
